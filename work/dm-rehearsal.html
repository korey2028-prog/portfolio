CASE 03 · AI WORKFLOW / CREATIVE OPS

DM 排练与角色手册

排练时需要读懂人物和剧情；真到现场，我需要一眼找到等谁、做什么、说哪句。

角色DM 实际使用者／手册整理与产品设计
技术Next.js／TypeScript／本地文档编译
状态手册已在门店流转；控制台为合成数据演示

THE PROBLEM

长文档适合备场，不适合拿着上场

角色本、主持人手册和线索分散在多份材料里。准备角色时要读完整，演出时却只来得及查当前场次。普通摘要还可能丢掉页码，或提前说出后面的真相。

因此我分别做 DM 控制台和演员手册：前者查人物、轮次和原文证据；后者分成长版备场材料与短版上场提示。

EVIDENCE PIPELINE

每个判断都能回到原件。

PDF 逐页提取→页内 Chunk→结构化故事模型→Exact Quote 回证→按轮次防剧透

WHAT SHIPPED

一份给排练，一份给现场

132 页演员手册

按人物关系、共同回忆和逐幕状态整理角色，供备场和排练时细看。

34 页上场朗读本

按九幕列出等待信号、现场动作、要说的台词和停止点。门店老板已转发给其他 DM。

DM 控制台演示

用合成剧本展示五分钟总览、人物关系、线索和轮次控制，可调主持模式与剧透级别。

原文回查

通过 documentId、页码、chunkId、原句和哈希定位依据。OCR 不完整时回原件核对；现场口令以门店总控为准。

ACTOR HANDBOOK

手册现在用到哪一步

我在离宫别院实际使用的版本是 132 页演员手册和 34 页九幕上场朗读本。长版含人物关系和备场清单，短版按幕次放 Cue、动作和台词。老板已把材料转给其他 DM；目前没有准备时间或现场失误率的统计。

另一个长版手册是 212 页、358 个书签项，检查过 PDF 元信息、文本层、字体和全部 212 页的渲染，没有发现空白页、黑页或主内容裁切。这是不同版本，仍需店内导演定版和实际排练确认；商业剧本原文及完整手册不在公开仓库分发。

VERIFIED STATUS

控制台演示的进度

  • 合成六人三轮 Demo 的 typecheck、lint、build 与 62 项测试通过。
  • 桌面与 390 px 移动端界面完成浏览器 QA。
  • 真实商业剧本只在本地授权范围内处理；未公开原文、OCR、线索、音视频或完整手册。
  • 真实模型 Provider 尚未做 API Key 烟测；部分剧本仍等待现场排练验收。
